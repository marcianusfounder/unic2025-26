Introdução à Engenharia de Software

Software • É o equipamento lógico ou suporte lógico de um computador digital • Inclui o conjunto de componentes necessários que permitem a realização  de tarefas específicas. • É a parte visual que nos permite interagir com o hardware.

## Página 10

Características de software

• Ele não é fabricado, é desenvolvido: um modelo de processo de

desenvolvimento que inclui análise, projeto, desenvolvimento,

implementação e avaliação é usado para obter um produto de qualidade.

![Imagem Extraída](file:///C:/Users/adria/OneDrive/Documentos/Marcianus Founder/PLANOS DE ESTUDOS — UNIC 2025-26/Z - Fontes Originais (Raw)/Base de Dados RAG/Media/Aula 01- Introdução_p10_img0.jpeg)

## Página 11

Características de software

• Ele não “estraga”, ele se deteriora: O software não falha como resultado

de elementos do ambiente que afetam o hardware; defeitos não

detectados nos estágios iniciais de sua vida útil farão com que o programa

falhe. O software não quebra, mas se deteriora, pelos seguintes motivos:

mudanças no ambiente em que o software opera, acumulação de erros,

falta de manutenção, complexidade crescente.

## Página 12

Características de software

• Embora o setor tenda a montar componentes, a maioria dos softwares é

desenvolvida sob medida.

• A reutilização é uma característica importante para um componente de

software de alta qualidade. O componente deve ser projetado e

implementado de modo que possa ser reutilizado em programas

diferentes.

## Página 13

Problemas no desenvolvimento de software

• Pobreza ao nível das previsões de tempo e esforço necessários para desenvolver um sistema.

• Programas de baixa qualidade.

• Altos custos de manutenção.

• Duplicação de esforços.

• Falta de envolvimento do usuário no processo de desenvolvimento.

• Falta de estudo prévio dos processos da organização a serem automatizados.

• Falta de planejamento, apenas atividades de codificação e edição, falta de documentação, poucos métodos formais, desenvolvimento baseado em testes e ensaios.

ENGENHARIA DE SOFTWARE

Disciplina ou área da ciência da computação que oferece

métodos, técnicas, princípios e procedimentos científicos para desenvolver

e manter softwares de qualidade, eficientes e confiáveis, com uma

orientação metódica, ordenada e quantificável para o aumento, a execução

e a manutenção de softwares.

É a disciplina que procura transformar as necessidades dos utilizadores em

sistemas de software de alta qualidade, de forma eficiente e fiável.

## Página 21

OBJETIVOS DA ENGENHARIA DE SOFTWARE

Aprimorar o design de aplicativos ou software para que sejam mais bem adaptados às necessidades das  organizações ou às finalidades para as quais foram criados.

Clareza de conceitos: melhor compreensão do domínio do problema e permite que seus resultados sejam reutilizados no desenvolvimento de outros sistemas no mesmo domínio

Proporcionar maior precisão nos custos e no tempo de desenvolvimento do projeto.

Aumentar a eficiência dos sistemas por meio da introdução de processos que possibilitem medir a qualidade do  software desenvolvido por meio de padrões específicos, buscando sempre a melhor qualidade possível de  acordo com as necessidades e os resultados a serem gerados

## Página 22

OBJETIVOS DA ENGENHARIA DE SOFTWARE

Melhor organização das equipes de trabalho na área de desenvolvimento e manutenção de software

Detectar, por meio de testes, possíveis melhorias para um melhor funcionamento do software desenvolvido

Melhor comunicação: as notações usadas na análise e no design permitem uma comunicação precisa,  porém abstrata, entre clientes, analistas, designers e programadores

Promova maior qualidade ao desenvolver aplicativos complexos. Melhoria da qualidade do trabalho de design: as  equipes de desenvolvimento exigem a decomposição do problema em partes independentes, e a análise e o  design permitem que o problema seja decomposto com sucesso

## Página 24

¿Como resolver os problemas?

Compreender o problema  (comunicação e análise).

Definir e ter clareza sobre o que a solução deve fazer, tarefas que ela deve realizar, dados necesarios para realizar as tarefas, formato os dados de entrada, de onde vêm os dados de entrada, como os dados são obtidos, como os dados interagem entre, qual será o resultado desejado e as restrições que podem existir no momento do processamento dos dados, formatos (formas de apresentar dados ou de onde os dados são obtidos quando feitos manualmente), fórmulas, fazer exemplos e verificar os resultados. Nessa fase, todos os requisitos e especificações do problema devem ser coletados.
